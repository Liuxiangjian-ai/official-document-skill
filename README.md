> **让 AI 像体制内笔杆子一样。**

`Official Document Skill` 是一个面向中文公文、政务应用文和机关材料写作的Skill，基于数百篇人民日报/光明日报等期刊的文章总结而成。它会根据用户提供的文种、场景、对象和材料，生成结构规范、语气稳妥、内容具体、少 AI 味、可直接交付的文本。

V1.2 在原版基础上进一步整合了多篇优秀公文案例、公文写作标准、法定公文格式规则。

V1.3 的新增优化重点是吸收 `humanizer-skill` 的二次审稿思路，专门处理看起来很工整但仍像 AI的问题：意义膨胀、假深刻、模糊主体、规则三连、同义词轮换、元话语和万能结论。

---

## 你有没有遇到过这种情况？

让 AI 写一份工作报告，它经常给出这样的文字：

```text
为深入贯彻落实高质量发展要求，进一步凝心聚力、开拓创新、真抓实干，
我单位持续强化责任担当，不断完善工作机制，全面推动各项工作走深走实、
提质增效，为谱写新时代事业发展新篇章贡献更大力量。
```

看起来很正式，仔细一看却有几个问题：

- 谁负责？做了什么？通过什么机制？到什么节点？有什么结果？

都没有。

这就是典型的 **AI 味**：抽象词很多，工作信息很少。

这个 Skill 要解决的就是这件事：把“正确但空”的文字，改成“具体、稳妥、能用”的公文表达。

## V1.3 相比原版升级了什么？

### 1. 升级为公文全流程写作引擎

原版重点解决 AI 腔、套话、空话问题。V1.3 增加了完整公文生成链路：

```text
识别场景 → 判断文种 → 提取事实 → 匹配结构 → 生成正文 → 降 AI 味 → 质量评分 → 交付
```

这意味着它不仅会改句子，也会先判断“这到底该写成通知、请示、报告、函，还是方案”。

### 2. 蒸馏了多篇优秀公文案例和写作标准

整合了公文写作资料中的法定公文格式、应用文模板、常见文种写法、格式错误、行文关系和交付校对规则。

新增强化内容包括：

- 通知、请示、报告、批复、函、纪要、通报、决定、通告等法定公文规则；
- 工作方案、工作总结、调研报告、汇报材料、讲话稿、简报、宣传稿等事务文书规则；
- 标题、主送机关、附件、落款、日期、上行文/下行文/平行文的格式约束；
- 请示与报告、通知与通告、批复与复函等易混文种辨析。

### 3. 整合 100 多篇人民日报文章蒸馏结果

V1.3 吸收了人民日报文章分析中的表达规律，但只保留可迁移到公文写作的部分：

- 事实承接判断；
- 背景不脱离具体任务；
- 问题切入要有真实表现；
- 段落要有明确功能；
- 强判断必须有强证据；
- 普通公文结尾回到责任、时限和办理要求。

它不会把基层通知写成评论文章，也不会把请示写成宣传稿。

### 4. 文种覆盖从 11+ 扩展到 20+

V1.3 支持更多实际工作场景：

| 类别 | 支持文种 |
|---|---|
| 法定公文 | 通知、通报、报告、请示、批复、函、纪要、决定、通告、公告、意见、议案 |
| 事务文书 | 工作方案、工作计划、工作总结、调研报告、汇报材料、简报/信息稿 |
| 会议材料 | 讲话稿、发言稿、表态发言、经验材料 |
| 面向公众 | 倡议书、公开信、感谢信、宣传稿、信访回复、政策解读 |
| 评论类 | 理论评论文章，但会严格限制其向普通公文迁移 |


### 5. V1.3 新增：humanizer 二次审稿

V1.3 在原有公文规则之外，新增一轮内部提问：

```text
如果这篇公文被退回，最可能被批评哪里像 AI 写的？
```

重点检查：

- 意义膨胀：普通事项被写成“重要里程碑”“充分彰显”；
- 假深刻：一句话后面连续接“推动、促进、助力、彰显”；
- 模糊主体：只写“相关部门”“有关方面”，没有责任对象；
- 规则三连：所有段落都强行写成三项并列；
- 同义词轮换：为了避免重复，把同一主体反复换称呼；
- 元话语：出现“下面从三个方面展开”“接下来我们来看”；
- 万能结论：结尾回到“谱写新篇章”，而不是责任、时限、报送要求。

## 它能做什么？

### 1. 从零生成公文

例如：

```text
用 $official-document-skill 写一份通知：区教育局通知各学校开展暑期校园安全排查，
重点查消防、用电、食堂、实验室危化品，6月30日前报送隐患台账。
```

Skill 会自动判断这是“通知”，重点写清对象、事项、要求、时限，而不是写成宣传稿。

### 2. 把口语材料转成正式公文

你可以直接给会议记录、工作要点、零散材料，它会整理成正式结构。

### 3. 降 AI 味、压缩套话

典型改写方向：

| AI 味表达 | V1.3 改写方向 |
|---|---|
| 凝心聚力、开拓创新 | 写清参与主体和共同目标 |
| 强化责任担当 | 明确责任单位、责任人、完成时限 |
| 走深走实、提质增效 | 写清落实到哪个环节、产生什么变化 |
| 形成闭环机制 | 写清发现、办理、反馈、复盘步骤 |
| 谱写新篇章 | 回到下一步任务、报送节点或工作目标 |

### 4. 检查文种和格式

它会识别这些常见问题：

- 报告里夹带请示事项；
- 请示多头主送；
- 通知写成讲话稿；
- 函写成命令；
- 标题文种和正文目的不一致；
- 提到附件但没有附件说明；
- 结尾过度宏大，脱离办理事项。

## 看一个简短例子

原句：

```text
我单位高度重视窗口服务工作，持续推进服务能力提升，全面优化服务流程，
不断增强群众满意度，推动政务服务提质增效。
```

V1.3 改写：

```text
我单位〔具体会议/部署名称〕后，〔数量〕周内完成〔事项，如综合窗口整合/材料清单梳理〕。
主要做了三方面工作：一是将〔原流程节点〕与〔新流程节点〕打通，减少群众跑动次数；二是将〔材料名称〕由〔原数量〕项压减至〔现数量〕项，并设置线上预审入口；三是前台窗口统一实行一次性告知，后台数据实时共享，避免群众重复提交。
调整后，〔窗口/事项〕平均办理时间由〔原时长〕缩短至〔现时长〕，群众现场补交材料情况明显减少。下一步将根据试运行反馈继续调整，重点解决〔具体问题，如跨区数据互通/老年人辅助办理〕。

需补充信息：

上述占位符中的具体动作、数据、事项名称（如无准确数据，可先以范围值标示并在成文前核实）。
是否需要写进制度名称、牵头科室、技术平台名称。
```

区别在于：

| 原句问题 | 改写动作 |
|---|---|
| “高度重视”没有信息 | 删除空泛表态 |
| “持续推进”没有宾语 | 改成具体环节 |
| “提质增效”没有证据 | 改成减少重复提交、等待时间 |
| 抽象判断多 | 增加对象、动作、机制 |

## 四项核心能力

### 1. 文种识别

先判断文种，再匹配结构。

| 用户意图 | 推荐文种 |
|---|---|
| 要求下级办理、告知事项 | 通知 |
| 向上级请求批准、支持、经费 | 请示 |
| 向上级汇报情况、进展、问题 | 报告 |
| 不相隶属单位商洽、询问、答复 | 函 |
| 答复下级请示 | 批复 |
| 安排专项行动 | 工作方案 |
| 复盘阶段工作 | 工作总结 |
| 分析情况并提出建议 | 调研报告 |
| 会议动员部署 | 讲话稿 |
| 快速反映动态 | 简报 / 信息稿 |

### 2. 事实密度增强

V1.3 会优先补足七个维度：

```text
谁负责 → 做什么 → 针对什么问题 → 通过什么机制 → 到什么时间完成 → 如何反馈 → 有什么结果
```

### 3. 语气克制

到什么程度，说什么话。

| 表达强度 | 使用条件 |
|---|---|
| 已启动、正在开展 | 只有部署或起步动作 |
| 有序推进、稳步推进 | 有计划、有步骤，但结果有限 |
| 取得进展、初见成效 | 有阶段性结果或对象反馈 |
| 取得明显成效、形成机制 | 有数据、制度、流程或稳定运行 |
| 重大突破、历史性成就 | 有权威认定、关键指标、行业比较或重大节点 |


### 4. Humanizer 二次审稿

这一轮追求不像模型自动生成。

| 二次审稿项 | 怎么改 |
|---|---|
| 意义膨胀 | 把“重要意义”改成具体任务、结果或依据 |
| 假深刻动词链 | 保留一个主动作，补对象和流程 |
| 模糊归因 | 写清来源、反馈渠道或删去 |
| 规则三连 | 按实际任务数量分条，不强凑三点 |
| 同义词轮换 | 重复最准确的主体名称 |
| 元话语 | 删除“下面是”“接下来”等说明 |
| 万能结尾 | 回到责任、时限、报送和下一步 |

## 一分钟快速测试

把下面这段复制给已加载 Skill 的 AI：

```text
用 $official-document-skill 写一份基层安全检查整改情况报告，要求正式、克制、去 AI 味，不要写成宣传稿。

文种：整改情况报告
使用场景：街道向区应急管理局报送安全检查整改情况
发文主体：XX街道办事处
面向对象：区应急管理局
材料要点：
1. 6月初，区应急管理局对XX街道辖区内沿街商铺、老旧小区、出租屋和小型仓储场所开展安全检查；
2. 检查发现部分沿街商铺存在灭火器过期、消防通道堆放杂物、电线私拉乱接等问题；
3. 个别老旧小区楼道内停放电动自行车，存在充电安全隐患；
4. 部分出租屋未按要求配备烟感报警器；

```

合格输出应当：

- 写成“报告”，不是宣传稿；
- 有主送机关；
- 如实写整改进展和存在问题；
- 下一步安排可执行；
- 不用“谱写新篇章”等万能结尾。

## 内置评分

生成后按六个维度自检：

| 维度 | 分值 | 看什么 |
|---|---:|---|
| 事实密度 | 20 | 有对象、动作、机制、数据或案例吗？ |
| 文种适配 | 20 | 结构、语气、结尾符合文种吗？ |
| 语气克制 | 15 | 判断强度和证据匹配吗？ |
| 句式自然 | 15 | 是否机械排比、句式单一？ |
| 抽象词控制 | 15 | 抽象词后是否有具体承接？ |
| 结构清晰 | 15 | 段落功能是否明确，推进是否自然？ |

附加 humanizer 检查：是否仍有意义膨胀、假深刻、模糊主体、规则三连、同义词轮换、元话语、万能结论。如果有，先修再交付。

处理规则：

| 分数 | 处理 |
|---|---|
| 90 分以上 | 可直接输出 |
| 80—89 分 | 局部压缩套话并增强具体性 |
| 70—79 分 | 重写问题段落 |
| 70 分以下 | 按文种结构整体重构 |

## 设计理念

V1.3 的核心是让文本回到机关材料最朴素的标准：

> **文种对、事实实、结构清、语气稳、责任明、结尾落地。**

人民日报语料提供的是表达规律，不是可复制的套话；优秀公文案例提供的是结构标准，不是机械模板。真正可交付的公文，最后一定要落到具体工作。
